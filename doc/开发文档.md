# 官网 · 开发文档

> 版本 0.1 ｜ 基于实际代码实现。改代码后回来更新本文。

## 1. 环境

- Node ≥ 22.5（用到 `node:sqlite`，必须带 `--experimental-sqlite`）
- 零外部依赖：只用 Node 内置模块，`npm install` 什么也不装

## 2. 目录结构

```
project.json    工程配置：version + name（派生二级地址/服务/用户/目录/库名）+ gateway.root
server.js       入口：装配 + listen，不写业务
src/
  config.js     env + project.json，配置唯一真源
  http/
    router.js   路由分发；加领域在 ROUTES 里挂（static 的 prefix 是空串，必须排最后）
    respond.js  cors/sendJson/sendBuffer/readJson/readBinary/parseUrl
    auth.js     管理后台鉴权（内存态 atoken）
    routes/
      health.js   健康检查（规范要求，勿删）
      public.js   前台只读接口，GET 之外一律 405
      images.js   出图 /api/image?id=
      admin.js    管理后台 /api/admin/*
      static.js   public/ 静态页兜底
  store/
    db.js       连接 + 建表（等幂）+ addColumnIfMissing
    index.js    数据层门面
    content.js  works/apps/news 三个同构模块 + 截图
    settings.js 站点设置 key/value
    images.js   图片元数据 + 字节
public/         前台 8 个页面 + admin.html + assets/（site.css/js、admin.css/js）
seed.js         本地示例内容（不进部署包）
selftest.js     端到端自检
deploy/         pack.sh / server-setup.sh / README.md
doc/            本文档集
```

## 3. 本地运行

```bash
npm start                  # 默认 8083，数据落 ./data/，浏览 http://127.0.0.1:8083/
npm run dev                # --watch 热重启
npm run seed               # 塞示例内容（只动本地 data/，已有内容就不覆盖）
npm run selftest           # 端到端自检，用临时数据目录，不碰 ./data
```

环境变量（见 `src/config.js`）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `project.json` 的 `service.port` | 监听端口 |
| `HOST` | `0.0.0.0` | 生产由部署 env 给 `127.0.0.1`，只让网关连得到 |
| `SITE_DATA` | `./data` | 数据目录，生产 `/var/lib/site` |

## 4. 加一个业务领域

1. `src/store/<领域>.js` —— SQL 与业务规则都在这层，只导出函数。
2. `src/store/db.js` —— 加表用 `CREATE TABLE IF NOT EXISTS`；**给已有表加列必须用 `addColumnIfMissing`**（SQLite 没有 `ADD COLUMN IF NOT EXISTS`，重复 ALTER 会直接报错，等幂是硬要求）。
3. `src/store/index.js` —— 挂上 `<领域>: require('./<领域>')`。
4. `src/http/routes/<领域>.js` —— 导出 `{ prefix, handle }`；`handle` 返回 `false` 表示"不归我管"。只做参数校验 + 调 store + 响应。
5. `src/http/router.js` —— 在 `ROUTES` 数组里挂上。
6. `selftest.js` —— 补断言。它是重构时唯一的保命网。
7. `doc/接口文档.md` —— 补路由与数据模型。

## 5. 部署

见 [deploy/README.md](../deploy/README.md)。要点：

- 对外地址：根入口 `https://todoo.top/`（本站占根）与二级前缀 `https://todoo.top/site/`，两条都通。
- 应用绑 `127.0.0.1:8083` 不对外；整机对外只放行 443 / 80 / 8080。
- 代码 `/opt/site` 与数据 `/var/lib/site` **分离**，重部署不碰数据。
- 改了 `project.json` 必须重跑 `register-app.sh`（`bash bin/deploy.sh site --config-only`），只 restart 不生效。
- 发布在平台仓做：`cd ../platform && bash bin/deploy.sh site`。

## 6. 常见坑

- **路由里加了 `/site` 前缀** → 404。网关的 `proxy_pass` 尾斜杠已经剥掉前缀了，代码里按 `/api/xxx` 写。
- **前端写 `/api/x`、`/assets/x` 绝对路径** → 二级前缀入口下打到网关根上 404。
  本站有两个入口（根 + `/site/`），前端地址**一律相对路径**（`api/works`、`assets/site.css`）。
- **新增了前台写入接口** → 违反需求。前台只读是产品决定，见需求文档第 6 节；`public.js` 里 GET 之外一律 405。
- **只给三张内容表中的一张加字段** → `content.js` 那套通用 SQL 会错位。要加三张一起加。
- **引了 Google Fonts** → 大陆取不到，首屏卡在字体超时上。只用系统字体栈。
- **忘了 `--experimental-sqlite`** → 启动即失败。`npm start` 已带，手工跑 node 时别漏。
- **给已有表 `ALTER TABLE ADD COLUMN`** → 第二次启动就崩。用 `addColumnIfMissing`。
- **数据目录路径硬编码** → 生产写到 `ReadWritePaths` 白名单外，systemd 报只读文件系统。用 `config.DATA_DIR`。
- **改了端口只 restart** → 不生效，nginx 还转发到老端口。重跑 `register-app.sh`。
