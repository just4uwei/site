# 官网（紫夜堂）· 架构文档

> 版本 0.1 ｜ 2026-09

## 1. 它在整台机器里的位置

一台云主机跑着多个互不相干的系统，共用一个 nginx 网关。本站的特别之处是**它占着域名根路径**。

```
                    ┌─────────────────────── 47.96.140.240 ───────────────────────┐
  https://todoo.top │  nginx                                                       │
  ─── 443 ─────────►│    gateway-ssl.conf ─┐                                       │
  http://…:8080     │    gateway.conf ─────┤                                       │
  ─── 8080 ────────►│                      │                                       │
                    │        include /etc/nginx/apps/*.conf                        │
                    │           ├─ site.conf     /site/…  ──┐ 剥掉 /site/          │
                    │           └─ harmony.conf  /harmony/… │ ──► 127.0.0.1:8081    │
                    │                                       │                      │
                    │        location / { include /etc/nginx/root-app.conf; }      │
                    │           └─ owner: site  ────────────┴──► 127.0.0.1:8083    │
                    └──────────────────────────────────────────────────────────────┘
```

`root-app.conf` 是**全机单例**：域名根只能归一个应用。谁占着看文件头的 `# owner:` 行。
它由平台的 `register-app.sh` 在应用声明 `gateway.root=true` 时渲染，不手改。
规范与排查见 [.claude/skills/multi-app-host/SKILL.md](../.claude/skills/multi-app-host/SKILL.md)。

**两条路进来的路径是同一套**：根入口没前缀可剥，二级前缀入口被 `proxy_pass` 尾斜杠剥掉，
到 Node 手里都是 `/api/works`、`/index.html`。所以业务代码只有一套，不感知自己挂在哪儿。

代价是前端地址必须写相对路径——这是本项目唯一因为"占根"而多出来的约束，
`selftest.js` 里有断言盯着首页不出现绝对路径引用。

## 2. 进程内部

```
server.js                  只装配：createServer + listen + 优雅退出
  └─ src/http/router.js    按 prefix 顺序分发，static 的 prefix 是空串排最后兜底
       ├─ routes/health.js   探活
       ├─ routes/public.js   前台只读；GET 之外 405
       ├─ routes/images.js   出图，ETag + 一年长缓存
       ├─ routes/admin.js    管理后台，除 login 外全要 atoken
       └─ routes/static.js   静态页，按 public/ → console/ 顺序找，路径穿越与扩展名双重过滤
  └─ src/store/            SQL 只在这层
       ├─ db.js            全库唯一一处 open + 建表（等幂）
       ├─ content.js       works/apps/news 同构，kind 决定表名
       ├─ settings.js      key/value，DEFAULTS 即白名单
       └─ images.js        元数据进库、字节落盘
```

没有 WebSocket 层：前台是纯只读展示，没有任何需要推送的东西，
所以模板自带的 `src/ws/` 在建站时就删了。

## 3. 几个决定与理由

**为什么三张内容表同构，而不是一张带 `type` 字段的表？**
一张表会让索引、约束和未来的分化都别扭（资讯迟早要加"置顶"，作品迟早要加"引擎"）。
三张同构表既保留了各自演化的余地，又让 `content.js` 能用一套 SQL 通吃——
代价是加字段得改三处，这个代价明确写在 CLAUDE.md 与需求文档里。

**为什么线上不留管理后台页面？**
管理台页面放在 `console/`，它不在 `deploy/pack.sh` 的打包清单里，
所以线上根本没有这个目录，访问 `/admin.html` 自然落到 404——不需要额外的开关或规则，
扫描器也就扫不到一个登录框。**接口留在线上**（否则没人能改内容），
本地管理台在登录页选「管理目标」为云端，请求跨域直打线上 `/api/admin/*`。
安全上真正守门的一直是密码哈希与 atoken；藏页面只是少一个被人试密码的入口，
但这个入口的成本是零，没理由留着。

**为什么静态文件由 Node 出，不让 nginx 直出？**
nginx 直出更快，但要给这个应用单独分叉一套网关片段模板（加 `root` 与 `try_files`），
而平台的约定是**所有应用共用一个 `app.conf.tmpl`**。整站几个页面几十 KB，
一次 `readFile` + ETag 完全够用，不值得为此破坏平台约定。

**为什么图片字节落盘而不是塞库？**
几百 KB 起的 BLOB 会把 SQLite 的 WAL 和备份都搞难看。落盘后出图就是一次 `readFile`，
还能带一年长缓存——`id` 与内容一一对应，改图就是传新图拿新 `id`，缓存永远不会过期变脏。

**为什么正文是纯文本而不是 Markdown/富文本？**
不解析就没有注入面。排版需求没大到值得引一个解析器 + 一个消毒器，
而这两样东西是长期的安全债。见需求文档第 6 节。

**为什么 `atoken` 不持久化？**
后台权限大（能改全站内容），token 存内存意味着一次重启就全体失效，
拿到旧 token 也没用。代价是我每次发版后要重新登录一次，可以接受。

## 4. 数据与红线

| 东西 | 位置 | 谁能碰 |
|---|---|---|
| 代码 | `/opt/site` | 每次发布整体覆盖 |
| 数据 | `/var/lib/site`（`site.db` + `images/` + `secret.key`） | **部署脚本只 `mkdir -p`，绝不删改** |
| 机密 | `/etc/site/site.env` 的 `ADMIN_PASSWORD_HASH` | 首次部署交互写入，之后保留不动 |
| 日志 | `/var/log/site/app.log` | — |

迁移数据目录时**必须带上 `secret.key`**。
`deploy/pack.sh` 打完包会被平台的 `deploy.sh` 检查有没有混进数据目录，混了直接失败。
