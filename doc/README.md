# doc/ - 官网 文档集

文档与代码同步：**改代码或部署前先读对应文档，改完回来更新它**。文档写实际实现，不写臆测。

| 文档 | 内容 | 什么时候更新 |
|---|---|---|
| [需求文档.md](需求文档.md) | 用户角色、功能需求 FR、非功能需求 NFR、安全需求与威胁模型、待办 | 需求变更时 |
| [架构文档.md](架构文档.md) | 架构图、组件职责、数据流、部署架构、技术选型与取舍 | 加组件/换选型/改分层时 |
| [接口文档.md](接口文档.md) | HTTP 路由清单、请求/响应格式、WebSocket 协议、数据模型表 | 加/改任何接口或表时 |
| [开发文档.md](开发文档.md) | 环境、目录结构、本地运行、调试、部署、运维、常见坑 | 加命令/踩到新坑时 |

部署规范不写在这里——见 `.claude/skills/multi-app-host/SKILL.md` 与 [deploy/README.md](../deploy/README.md)。

## 写文档的纪律

- **一个大功能模块一个文档**。单个文档超过 ~500 行就拆子目录（如 `doc/app-native/`、`doc/app-webview/`），并在本 README 挂索引。
- 写"是什么、为什么这么定、在哪个文件"，不复制粘贴代码。引用代码写 `文件路径:行号`。
- 已知坑单独成节——它比正确用法更值钱。
- 事实与臆测分开：拿不准的标"待验证"，不要写成结论。
