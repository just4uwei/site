# 官网 · 接口文档

> 版本 0.1 ｜ 2026-09 ｜ 与 `src/http/routes/` 同步，改路由回来更新本文。

## 0. 地址与前缀

路径**一律按无前缀写**。线上两条路都通到同一套路径：

| 入口 | 前缀 | 网关做了什么 |
|---|---|---|
| `https://todoo.top/` | 无 | `/etc/nginx/root-app.conf` 反代，没有前缀可剥 |
| `https://todoo.top/site/` | `/site` | `/etc/nginx/apps/site.conf`，`proxy_pass` 尾斜杠剥掉前缀 |

明文兜底同理：`http://47.96.140.240:8080/` 与 `.../site/`。

所以前端拼地址**一律用相对路径**（`api/works`），不要写 `/api/works`。

响应统一 `application/json; charset=utf-8`（出图与静态文件除外）。
出错格式恒为 `{"error": "中文说明"}`。

## 1. 公共（无鉴权，只读）

前台接口 **GET 之外一律 405**。站点没有任何写入型前台接口，这是需求，不是遗漏。

### GET /api/health
健康检查。规范要求，网关与 `register-app.sh` 靠它探活。

```json
{ "ok": true, "name": "site", "version": "0.1.0" }
```

### GET /api/site
站点设置 + 各模块已发布条数 + 全站最近更新时间。首页抬头的字段行与导航计数用它。

```json
{
  "site": { "site_title": "todoo", "site_tagline": "…", "site_intro": "…",
            "about_body": "…", "contact_email": "", "contact_note": "",
            "icp": "闽ICP备2026032416号-1", "footer_note": "" },
  "counts": { "works": 2, "apps": 1, "news": 2 },
  "updated": 1789115616638,
  "name": "site", "version": "0.1.0"
}
```

`site` 的键集合固定，就是 `store/settings.js` 的 `DEFAULTS`——白名单外的键写不进也读不出。

### GET /api/works ｜ /api/apps ｜ /api/news
已发布列表，**不含 `body`**（列表页用不上，省流量）。

| 查询参数 | 默认 | 说明 |
|---|---|---|
| `limit` | 60 | 1–200，超出截断 |

```json
{ "items": [ { "id": 1, "title": "…", "subtitle": "…", "tag": "…", "summary": "…",
               "cover_id": 3, "link_url": "", "link_label": "", "dateline": "2026-06",
               "sort": 0, "status": "published", "created_at": 0, "updated_at": 0 } ] }
```

### GET /api/works/item?id=N ｜ /api/apps/item ｜ /api/news/item
详情。**草稿一律视作不存在（404）**，前台看不到未发布内容。

```json
{ "item": { "...": "含 body 的完整记录" },
  "shots": [ { "id": 1, "image_id": 4, "caption": "", "sort": 0 } ],
  "prev": { "id": 2, "title": "…" },
  "next": null }
```

`prev` / `next` 与列表同序（`sort` 升序，同 `sort` 按创建时间倒序）。

### GET /api/image?id=N
出图。返回图片字节，`Content-Type` 是上传时的 MIME。

- `ETag` 取内容 sha256 前 16 位；带 `If-None-Match` 命中回 **304**
- `Cache-Control: public, max-age=31536000, immutable`——id 与内容一一对应，改图就是传新图拿新 id
- 图不存在或磁盘文件丢了都回 404（不 500）

### 静态站点
`public/` 下的页面与资源由 `routes/static.js` 兜底出，支持干净地址（`/works` → `works.html`）。
`/api/` 开头的路径不会被当文件找，未知 API 回 JSON 404。

## 2. 管理后台 `/api/admin/*`

除 `login` 外全部需要 `Authorization: Bearer <atoken>`。
`atoken` 是**内存态**，服务重启即失效，需重新登录——后台权限大，有意不持久化。
未登录一律 401，前端收到 401 就踢回登录页。

### POST /api/admin/login
`{ "password": "…" }` → `{ "atoken": "…" }`；密码错 401。

生产校验 `ADMIN_PASSWORD_HASH`（scrypt，写在 `/etc/site/site.env`）；
本地开发无哈希时回落明文 `ADMIN_PASSWORD`，默认 `admin`。

### 内容（`kind` ∈ `works` | `apps` | `news`，非法值 400）

| 方法与路径 | 说明 |
|---|---|
| `GET  /api/admin/content?kind=` | 列表，**含草稿** |
| `GET  /api/admin/content/item?kind=&id=` | 详情 + 截图，含草稿 |
| `POST /api/admin/content/save` | 有 `id` 则更新，无则新建。标题为空 400 |
| `POST /api/admin/content/status` | `{ kind, id, status }`，`status` 非 `published` 一律按 `draft` |
| `POST /api/admin/content/delete` | `{ kind, id }`，连带清掉该条的截图关联 |

`save` 只采纳这些键：`title` `subtitle` `tag` `summary` `body` `link_url` `link_label`
`dateline` `cover_id` `sort` `status`。其余（`id` 之外）一概忽略。

### 截图

| 方法与路径 | 说明 |
|---|---|
| `GET  /api/admin/shots?kind=&id=` | 某条内容的截图，按 `sort` 升序 |
| `POST /api/admin/shots/add` | `{ kind, id, image_id, caption, sort }` |
| `POST /api/admin/shots/delete` | `{ id }`（截图关联的 id，不是图片 id） |

### 图库

| 方法与路径 | 说明 |
|---|---|
| `GET  /api/admin/images?limit=` | 图片元数据列表，最多 500 |
| `POST /api/admin/images/upload?alt=` | **请求体是原始字节**，`Content-Type` 就是图片类型 |
| `POST /api/admin/images/delete` | `{ id }` |

上传白名单：`image/png` `image/jpeg` `image/webp` `image/gif` `image/svg+xml`，
白名单外 400。单张上限 8M（网关 `maxBodySize` 12m 还会在更外层挡一道）。

删图后：引用它的 `cover_id` 被外键置空（`ON DELETE SET NULL`），
挂着它的截图被级联删除（`ON DELETE CASCADE`）——不会留死链。

### 站点设置

| 方法与路径 | 说明 |
|---|---|
| `GET  /api/admin/settings` | 全量读，缺的键回落默认值 |
| `POST /api/admin/settings` | 批量写，**白名单外的键静默忽略**，返回 `{ updated, site }` |

白名单就是 `store/settings.js` 的 `DEFAULTS` 键集合。`icp` 默认 `闽ICP备2026032416号-1`。

## 3. 数据模型

见 `src/store/db.js`（那里是唯一的建表处）。摘要：

| 表 | 说明 |
|---|---|
| `works` / `apps` / `news` | 三张**同构**内容表，字段与索引完全一致 |
| `shots` | 截图关联：`owner_kind`（表名）+ `owner_id` + `image_id` + `sort` |
| `images` | 图片元数据；字节落在 `/var/lib/site/images/<id>`，不进库 |
| `settings` | 站点设置 key/value |

`shots.owner_kind` 存的是表名，但外部输入必须先过 `content.isKind()` 白名单——
那是唯一把外部输入变成 SQL 表名的地方，是防注入的闸门。
