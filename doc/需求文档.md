# 官网 · 需求文档

> 版本 0.1 ｜ 2026-09 ｜ 与代码同步，改了需求回来更新本文。

## 1. 项目定位

todoo.top 的对外站点。给**路过的人**看：我做了哪些游戏、写了哪些 App、最近有什么更新。
做到「陌生人点进来，五秒内知道这是谁的站、有什么东西、去哪儿下」就算成功。

起因：ICP 备案（闽ICP备2026032416号-1）2026-09 下来了，域名可以做正式站点了。
在此之前 `todoo.top/` 根路径一直返回 404（强制二级前缀），现在由本站接管。

## 2. 命名

| 名字 | 用在哪 |
|---|---|
| 紫夜堂 | **站名**，页面上露出来的那个。存在设置表 `site_title`，后台可改，不写死在代码里 |
| 官网 | 平台注册表（`apps.json`）与运维语境下的显示名 |
| `site` | 代码内部标识 = 二级地址名 = 服务名 = 用户名 = 目录名 = 库名（`project.json` 的 `name`） |

## 3. 用户角色

| 角色 | 能做什么 | 不能做什么 |
|---|---|---|
| 访客（无账号，占 99.9%） | 浏览首页、游戏作品、App、资讯、关于页；点外链去下载 | **不能评论、留言、投稿、点赞、注册**——站点不提供任何写入口 |
| 管理员（就我一个） | 管理后台登录后增删改三类内容、传图、改站点设置与备案号 | — |

## 5. 非功能需求 NFR

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 可用性 | 单机 systemd `Restart=always`；`MemoryMax`/`CPUQuota` 封顶不拖垮同机其它系统 |
| NFR-2 | 数据隔离 | 独立数据目录 `/var/lib/site` + 独立运行用户，`ProtectSystem=strict` 内核级保障 |
| NFR-3 | 部署 | 幂等一键部署；重部署不影响线上在库数据 |
| NFR-4 | 字体可达 | 只用系统字体栈。**不引 Google Fonts**——大陆取不到，会让整站首屏卡在字体超时上 |
| NFR-5 | 双入口一致 | 根入口与 `/site/` 二级前缀入口渲染结果必须一致；前端一律相对路径 |
| NFR-6 | 出图 | 图片带 ETag + 一年长缓存；`id` 与内容一一对应，改图＝传新图拿新 id |
| NFR-7 | 无障碍 | 键盘焦点可见；尊重 `prefers-reduced-motion`；图片有 alt |
| NFR-8 | 线上无后台页面 | 管理台页面不进部署包，线上 `/admin.html` 必须 404；接口保留（本地管理台跨域连） |
| NFR-9 | 页面真能打开 | 前端全靠 JS 渲染，服务端自检覆盖不到；`selftest-pages.js` 用 headless 浏览器逐页验渲染结果 |

## 6. 明确**不做**的事（重要）

这一节是给未来的自己和 AI 看的：下面这些不是"还没做"，是**决定不做**。

| 不做 | 为什么 |
|---|---|
| 评论、留言板、联系表单 | 一个人维护不过来，且要承担 UGC 内容审核责任（境内备案站点尤其）。有事发邮件。 |
| 点赞、浏览计数、访客统计面板 | 数字会反过来影响我写什么。想看流量去看 nginx 日志。 |
| 用户注册/登录 | 前台没有任何需要身份的功能。不收集就不会泄露。 |
| 富文本/Markdown 正文 | 正文是纯文本分段渲染，不解析 HTML，从根上断掉注入。排版需求没大到值得引一个解析器。 |
| 站内搜索 | 内容量三位数以内，导航够用。 |

因此 `src/http/routes/public.js` 里 GET 之外一律回 405，且**根本不存在**写入型前台接口。
`selftest.js` 有断言盯着这条。要推翻这个决定，先改本节。

## 7. 内容模型

三类内容（游戏作品 / App / 资讯）**字段完全相同**，只是展示形态不同：

| 字段 | 说明 |
|---|---|
| `title` / `subtitle` | 标题与副标题 |
| `tag` | 作品/App 是平台标签（`Windows · Steam`），资讯是分类（更新/公告/幕后） |
| `summary` | 列表页那一句 |
| `body` | 详情正文，纯文本，空行分段 |
| `cover_id` | 封面图（App 当图标用），指向 `images` 表 |
| `link_url` / `link_label` | 外链按钮，留空则不显示按钮 |
| `dateline` | 给人看的日期，`2026-09` 这种粒度就够；留空回落到创建日期 |
| `sort` / `status` | 排序（越小越前）与 草稿/已发布 |

同构是有意的：一套 SQL、一套管理后台通吃三类。**要加字段就三张表一起加**，别让它们分叉。

展示形态的差别只在前端：作品是宽卡片配大封面，App 是卡片配方形图标，资讯是按日期排的行。
